1 Tóm tắt nhanh (TL;DR)

Có — lọc theo ngày + tự quét nền + tự xử lý file mới

Chọn folder → index SQLite → UI chỉ query theo khoảng ngày tạo. Sau đó app tự theo dõi folder (FS watcher + poll ~20s): chỉ INSERT file XML mới, UI tự refresh theo khoảng ngày đang chọn, và tự gửi HIS các file waiting (cần đã cấu hình HIS). Không cần bấm «Quét lại» / «Xử lý» cho luồng thường ngày.

✅ UI / bảng danh sách

  • Chỉ load file theo khoảng ngày tạo
  • Đổi khoảng ngày → query lại SQLite (nhanh)
  • Tự refresh khi có file mới / auto-process xong

✅ Background (tự động)

  • notify watcher + poll 20s
  • Chỉ insert path chưa có trong DB
  • Auto-process waiting (cả ngày của file mới / hôm nay)

2 Hai tầng: Disk index vs UI list

Hiểu rõ hai tầng này sẽ tránh nhầm: “không load 15k lên UI” không có nghĩa là bỏ quét folder. App tách thành:

Disk
Thư mục tracking, ví dụ D:\DATA_PACS\KR800. Máy KR-800 xuất file *.xml vào đây (folder có thể lẫn file khác của PACS).
SQLite
Bảng xml_files = index các file đã biết: path, size, status, created_at (parse từ tên file …_YYYYMMDD_HHMMSS_…). Có thể có hàng chục nghìn bản ghi.
UI
Chỉ SELECT … WHERE created_at BETWEEN from AND to theo khoảng “Ngày xử lý” trên màn KR-800. Render bảng từ kết quả đã lọc.
HIS API
Nút Xử lý chỉ lấy file status = waiting trong cùng khoảng ngày tạo, gửi kết quả đo về HIS.

3 Luồng chính end-to-end

1
UI

Mở màn KR-800

App đọc khoảng ngày đã lưu (hoặc mặc định hôm nay), gọi list_xml_files(from, to) → hiện bảng theo ngày tạo. Chưa có folder thì bảng trống, nhắc chọn thư mục.

2
UI

Cấu hình HIS (nếu chưa)

Vào Cấu hình: API URL, tài khoản, đăng nhập HIS, lưu token. Cần có token trước khi bấm Xử lý.

3
Disk + DB

Chọn thư mục tracking

Backend quét *.xml trên disk, upsert vào SQLite (index). Không trả full danh sách 15k về UI. Xong scan → UI reload list theo khoảng ngày đang chọn.

4
UI

Chỉnh khoảng «Ngày xử lý»

Đổi Từ / Đến (datetime) → app query lại SQLite theo created_at. Bảng cập nhật ngay; không cần quét lại folder.

5
Tự động

File XML mới xuất ra folder

Watcher / poll phát hiện → chỉ INSERT path chưa có (status = waiting) → event kr800:files-indexed → UI refresh theo khoảng ngày đang chọn.

6
HIS · tự động

Tự xử lý file waiting

Backend gọi pipeline process (cùng logic nút «Xử lý») cho khoảng ngày của batch mới (00:00–23:59). Match BN → map → gửi HIS. Event kr800:auto-process + kr800:file-progress cập nhật UI. Nút «Xử lý» vẫn dùng được khi muốn chạy tay.

4 Khi chọn folder / Quét lại — chi tiết backend

4.1. Chọn thư mục

  1. User bấm Chọn thư mục → native folder picker.
  2. Command set_tracking_folder_and_scan:
    • Lưu path vào device_config.
    • read_dir folder, lấy mọi file .xml.
    • Parse created_at từ tên file (vd. …_20260714_173000_… → 2026-07-14 17:30:00).
    • Load map path hiện có trong DB một lần.
    • File mới → INSERT (status = waiting).
    • File đã có, metadata đổi → UPDATE (giữ nguyên status xử lý).
    • File không còn trên disk → prune (có bảo vệ nếu giảm đột biến).
  3. Trả về summary (số quét / thêm / cập nhật / gỡ / tổng tracked) — không kèm mảng files.
  4. UI gọi list_xml_files(from, to) với khoảng ngày hiện tại → vẽ bảng.

4.2. Quét lại

rescan_tracking_folder = bước quét giống trên, dùng lại folder đã lưu. Có khóa chống spam: không gọi chồng khi đang scan.

Lưu ý về thời gian quét disk

Nếu folder PACS chứa rất nhiều file không phải XML, lần quét vẫn có thể mất thời gian vì phải duyệt disk. Đó là chi phí index, không phải chi phí render 15k dòng trên UI. Nên để XML KR-800 ở thư mục chuyên biệt nếu có thể.

4.3. Bảo vệ prune (tránh mất index)

  • Disk thấy 0 XML nhưng DB còn bản ghi → không xóa.
  • Sắp xóa > 50 bản ghi và > 10% tổng → bỏ qua prune, báo pruneSkipped trên UI (tránh case 15 464 → 2 như log máy thật).

5 Lọc theo ngày tạo — trả lời trực tiếp

Có thể lọc file theo ngày ngay khi chọn folder không?

Có. Ngay sau khi scan xong, app không đẩy 15k file lên màn hình. Nó dùng đúng khoảng «Ngày xử lý» đang hiển thị (mặc định hôm nay) để SELECT từ SQLite. Bạn thấy ngay các file có ngày tạo trong khoảng đó.

Không cần load 15k file?

Đúng với tầng UI. React state / bảng chỉ chứa file trong khoảng ngày. Tầng SQLite vẫn có thể index toàn bộ XML đã quét (để lần sau đổi ngày hoặc xử lý ngày khác không phải quét disk lại).

Đổi ngày có phải quét folder lại không?

Không. Chỉ query DB theo created_at. Chỉ cần «Quét lại» khi có file XML mới xuất ra disk mà app chưa index.

Nguồn ngày tạo

Ưu tiên parse từ tên file KR-800 (YYYYMMDD_HHMMSS), không phải thời điểm file copy vào folder. Ví dụ:

HCM2607070269_20260707_145000_TOPCON_KR-800_4780634.xml → created_at = 2026-07-07 14:50:00

Khoảng «Ngày xử lý» trên UI (datetime-local) được chuẩn hóa thành YYYY-MM-DD HH:mm:ss (mốc cuối khoảng lấy hết phút, giây :59 nếu không nhập giây).

6 Luồng «Xử lý» gửi HIS

1

Chọn khoảng thời gian

Cùng khoảng ngày tạo dùng để list file và gọi API danh sách người bệnh HIS.

2

Lấy file chờ xử lý

SQL: status = 'waiting' AND created_at BETWEEN from AND to — không duyệt 15k file trên UI.

3

Pipeline từng file (tối đa 5 song song)

Parse XML → hash nội dung (bỏ qua trùng) → tìm BN theo mã hồ sơ → map SPH/CYL/AX → POST HIS → cập nhật status / lỗi.

4

Cập nhật UI

Event kr800:file-progress cập nhật từng dòng; cuối cùng trả lại list file trong khoảng (không full table).

7 Trước vs sau tối ưu

Hạng mục Trước (gây treo ~17h36) Sau
Sau scan / rescan Trả về & setState cả ~15k file Chỉ summary; list lại theo khoảng ngày
Mở màn / list SELECT full device SELECT theo created_at range
Upsert DB N lần SELECT EXISTS + UPDATE/INSERT 1 map + transaction; skip nếu không đổi
Prune file mất Xóa mọi path không thấy trên disk Bảo vệ khi giảm đột biến / disk rỗng
Sau process HIS Trả full list device Trả list trong khoảng xử lý
Spam «Quét lại» Dễ gọi chồng Khóa scanInFlight

8 Câu hỏi thường gặp

Tại sao quét folder vẫn có loading?

Vì app đang index XML từ disk vào SQLite. UI hiện “Đang quét thư mục…” và khóa nút quét để tránh chạy chồng. Sau khi xong, bảng chỉ load file theo ngày — nhanh.

File hôm qua / tuần trước xem thế nào?

Đổi «Ngày xử lý» (Từ – Đến). App query DB ngay, không cần chọn lại folder. Nếu file đó chưa từng được scan vào DB, hãy «Quét lại» một lần.

File mới xuất từ máy — có cần bấm Quét lại không?

Không (luồng thường). App tự index trong vài giây–~20s (poll). Kiểm tra khoảng «Ngày xử lý» có khớp created_at trong tên file. «Quét lại» chỉ khi cần full sync / sửa lệch index thủ công.

Tự xử lý HIS có chạy không nếu chưa login?

App chỉ auto-process khi đã cấu hình API URL + username. Có thể login tự động bằng mật khẩu đã lưu khi gửi HIS. Nếu thiếu cấu hình, file vẫn được index (waiting) và message báo bỏ qua tự xử lý.

Thấy thông báo bỏ qua xóa hàng loạt?

App phát hiện disk đang “thiếu” quá nhiều file so với DB (có thể mount lỗi / folder tạm rỗng). Cố ý không xóa index để tránh mất dữ liệu tracking như sự cố test trước. Kiểm tra lại path folder rồi quét lại khi disk ổn định.

Thao tác khuyến nghị hàng ngày
  1. Mở app → cấu hình HIS (một lần) → chọn folder tracking (một lần).
  2. Giữ khoảng ngày = ca hôm nay (mặc định) để xem bảng.
  3. Để app chạy (có thể ẩn tray) — XML mới sẽ tự index + tự gửi HIS.
  4. Theo dõi status từng dòng nếu có lỗi (không thấy BN, mapping…).
  5. «Quét lại» / «Xử lý» chỉ khi cần can thiệp thủ công.
